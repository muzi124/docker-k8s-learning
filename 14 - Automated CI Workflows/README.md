### 001 Section Intro Automation（章节介绍）

- 介绍 CI（持续集成）的价值：**自动化构建、测试、校验**，减少人工操作，避免人为失误。
- 本章基于 GitHub Flow，不是完整复杂 GitLab CI/Jenkins，是轻量的 DevOps 工作流。

### 002 The Pull Request（PR 拉取请求）

- GitHub Flow 核心：**分支开发 → Pull Request (PR) → 代码评审 → 合并到主分支 main**
- PR 作用：提交代码变更，给团队做代码审查；**PR 可以绑定自动化流水线**。
- 核心思想：主分支`main`永远保持可运行、可发布状态，不直接在 main 上写代码。

### 003 Automation is the Glue of DevOps 自动化是 DevOps 的粘合剂

> 
> 核心一句话：**自动化串联整个 DevOps 流程：代码提交 → 自动构建镜像 → 自动测试 → 漏洞扫描 → 自动推送镜像仓库**

- 没有自动化，DevOps 只是手工操作；CI 就是把重复步骤交给机器。
- 典型场景：提交代码后自动构建 Docker 镜像，自动跑单元测试，自动扫描镜像漏洞。
- 失败阻断：构建 / 测试失败，**禁止合并 PR**，防止坏代码进主分支。

### 004 Basic PR Workflow 基础 PR 工作流

最简流水线：

1. 开发者新建分支写代码
2. 提交分支，发起 PR
3. 触发 CI：自动构建 Docker 镜像、基础校验
4. CI 全部通过 → 代码评审 → 合并 main 分支
5. 合并后自动打包推送镜像到镜像仓库

### 005 Intermediate PR Workflow 中级 PR 工作流

在基础版增加能力：

- 多阶段测试（单元测试、集成测试）
- 镜像漏洞扫描（扫描 Docker 镜像里面的安全漏洞）
- 缓存优化：缓存依赖，加快 CI 构建速度
- 分支策略区分：PR 阶段只做构建 + 测试；合并 main 后才推送镜像仓库（**PR 阶段不推送正式镜像**）

### 006 Advanced PR Workflow 高级 PR 工作流

进阶生产级流水线：

- 多平台镜像构建（同时构建 amd64、arm 架构镜像，比如 x86 电脑 + 树莓派）
- 镜像版本标签管理（根据 git commit 自动生成版本号）
- 环境区分：开发镜像、预发布镜像、生产镜像
- 人工审批卡点：部分高危发布需要人工确认后才部署到生产环境
- 自动回滚机制

# ✅ 本章核心知识点总结

1. **GitHub Flow**：简单分支模型，`main`分支永远稳定；所有修改走分支 + PR。
2. **CI 持续集成**：代码提交自动触发构建、测试、镜像扫描，**提前发现问题**。
3. 流水线分层：基础 → 中级 → 高级，逐步增加测试、安全扫描、多架构、版本管理。
4. 核心原则：
   - PR 阶段：只做**构建 + 校验 + 测试**，不推送生产镜像
   - 合并 main 之后，才构建并推送正式镜像到 Registry
5. 本章和 Docker 的关系：CI 流水线里**最常见动作就是自动构建 Docker 镜像**。
