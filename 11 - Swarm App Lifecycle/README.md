这个章节聚焦 **Docker Swarm 集群里应用完整生命周期**，包含应用开发、构建、部署、秘钥管理、健康检查、滚动更新。

## 核心知识点

### 1. Docker Secrets（容器秘钥管理，01 节）

- 作用：**安全保存敏感信息**（密码、数据库密钥、token），不要硬编码进镜像 / Compose 文件。
- 本地 Docker 环境也可以测试 Secrets（不一定必须 Swarm 集群）。
- 原理：秘钥不会存入镜像，运行时挂载到容器内存临时文件，不写入磁盘。

> 
> 注意：普通 docker-compose（非 swarm 模式）对 secrets 支持有限，完整能力需要`docker swarm`集群。

### 2. 完整应用生命周期：Dev → Build → Ship → Run（02 节）

应用完整流程：

1. **开发 (Dev)**：本地用`docker compose`开发调试，多 Compose 文件叠加（基础 + 开发 + 生产，`-f`加载多个 compose）
2. **构建 (Build)**：构建镜像，版本打标签
3. **发布 (Ship)**：推送到镜像仓库
4. **运行 (Run)**：在 Swarm 集群部署服务

- 多 Compose 文件：用多个 yml 分层，区分开发环境、生产环境配置，**不要写一份超大 compose**，便于复用和区分环境。

### 3. Swarm 服务滚动更新 Service Updates（03 节）

- 服务升级：更新镜像版本，Swarm 默认**滚动分批更新**，不会一次性全部停掉服务。
- 可以自定义参数：批次大小、更新间隔、失败回滚策略。
- 核心命令：`docker service update`，支持修改镜像、环境变量、端口、资源限制等。
- 风险控制：如果新版本健康检查失败，自动停止更新，避免全部服务挂掉。

### 4. Healthcheck 健康检查（04 节，重点）

两种定义位置：

1. **Dockerfile 内写 HEALTHCHECK**：镜像自带健康检测规则，镜像打包就内置
2. **Compose /docker service 里定义**：部署层单独指定检测规则，覆盖镜像配置

- 作用：判断容器内应用是否真的正常，**不是只看容器进程有没有跑**（进程活着不代表服务可用）
- 检测参数：检测命令、超时时间、间隔、重试次数、启动等待时间 (start_period)
- Swarm 会根据健康状态，自动替换不健康的容器，实现自愈。

> 
> 示例场景：PHP Laravel 项目演示健康检查配置。

### 5. Swarm Mastery 基础介绍（06 节）

- Swarm 就是 Docker 原生集群编排，不需要额外装 K8s，适合中小型容器集群。
- 特点：内置服务发现、负载均衡、滚动更新、秘钥、overlay 网络。
