# Section 01: Quick Start (快速入门)

1.有Docker为什么还要学习Kubernetes？

  使用 Docker 时，你仍然需要手动设置服务器间的网络，包括安全策略、DNS、存储、负载均衡、备份、监控等。涉及数十个相关容器，这带来了与容器化应用之前相当甚至更多的工作量。
  Kubernetes是一个开源的多服务器集群系统。它协调了所有需要的工具，以实现托管数十、数百甚至数千个应用的真实解决方案。 可以把它看作是一种抽象，隐藏了运行多个容器化应用所需的所有关键部分。

  Kubernetes 对服务器群的意义，就像 Docker 之于 单一服务器一样。 它是一组程序和API，通过一个CLI控制多个Docker引擎。

2.docker的建立
  
是层次递进，第一层先拉取python库和相关环境配置，第二层拉取第三方的插件，用pip等，第三层则是项目源代码。

3.docker的注册表

主要是确保不同系统拉取的配置相同，解决了本机做好的镜像无法快速批量部署到多台机器的问题

4.不同系统，拉取相同镜像，为什么会能运行？

镜像内置程序全套运行依赖，不依赖宿主系统预装软件；Docker 借助 Linux 内核 Namespace+Cgroups 做资源隔离，统一适配内核系统调用；Windows/macOS 端 Docker 会内置轻量化 Linux 运行环境屏蔽系统差异；只要 CPU 架构匹配、安装 Docker 引擎，任意主流系统都能运行同一镜像。

5.Docker 容器核心特性（镜像→容器运行机制）

命名规范：标准名称为OCI 容器（Docker 容器），不能直接称作 docker/dockers；

启动逻辑：docker run基于只读镜像创建独立运行容器，自动执行 Dockerfile 定义的启动命令；

隔离底层：依托 Linux 内核Namespace（命名空间）+Cgroups（控制组）实现应用隔离，容器拥有独立文件视图、网卡、私有 IP，默认看不到宿主机外部进程；

技术本质：不属于虚拟机硬件虚拟化，是轻量级应用隔离技术；

多实例隔离：同一台机器可从同一个镜像启动多个容器，实例之间文件系统、运行环境完全隔离，单个容器内的文件修改不会影响其他容器。

6.docker指令
